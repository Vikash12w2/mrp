# Version A: offline decentralized mobile recharger planning (spec for the code in `mrp/`)

Local grouping by negotiation + per-group two-shot SMT (the repo's algorithm, run once per group).

## 1. Model and assumptions
| # | Assumption |
|---|---|
| A1 | Workers are **broadcast-only**: they send ID, loop, full charge, battery, position. They do not negotiate, plan, vote or relay. (Radio is our addition; the repo/paper do not model it.) |
| A2 | **Range sensing:** a recharger learns only about workers it hears whose whole loop lies inside its region. A worker heard by no recharger is invisible to the agents; the experiment observer still reports it as outside_all_regions. |
| A3 | **Anchor** = the physical setup position and fixed grouping/region centre. Phase 1 selects the hypercycle start inside the region; Phase 2 preserves it. `deployment.plan_deployment` routes from anchor to selected start before workers begin. Setup duration is reported separately from hypercycle efficiency. `deploy.pick_anchors` proposes initial physical deployment locations. |
| A4 | **Region** = free cells in the Chebyshev box of radius R_s around the anchor (R_s=6 -> 13x13). Planning range = sensing range. R_s is a user input. |
| A5 | **Communication** recharger-to-recharger only, range R_c = 2 R_s; neighbours = anchors within 2 R_s (regions overlap). No worker-request or trajectory relaying. Setup readiness and finish-time summaries propagate over neighbor links for the component start barrier. |
| A6 | Reliable channel inside range except where ACK retries are exhausted (then the peer is treated as failed). Fail-stop robots (section 5). |
| A7 | Determinism: ID tie-breaks, fixed seed, each solve in a fresh process (Z3 tie-breaking otherwise depends on earlier solves), no solver wall-clock timeouts. Setup communication has its separate heartbeat timeout. |
| A8 | Repo model: each loop waypoint is one time step (may be several cells apart), per-step energy `req`, 21 motion primitives, recharge in (0, delta_max], 8 neighbour offsets. |

## 2. Parameters (`params.py`)
R_s (default 6; size classes: side <=20 -> 6, <=40 -> 8, <=80 -> 12, else 16), R_c=2R_s, u1/u2/u3 = 1/0.1/0.01, cap_n None (optional explicit worker-count limit; cap_util is accepted only as an ignored legacy argument), K_round 20, K_swap 10, K_unclaimed 10, K_T 4, K_refine 0, refine_min_gain 0.5, hb_period 1, k_missed 3, group_mode two_shot, one_shot_H 0 (= instance T), one_shot_max_workers 1, seed 0, retries 3, collisions True, exclusive_recharge False.

## 3. Pipeline (each recharger runs it locally)
1. **Discover:** beacons (ID, anchor) give neighbours; hear worker broadcasts; candidates = workers whose whole loop is in the region.
2. **Exchange candidate lists** with neighbours (ACK/retry).
3. **Local load-aware auction** (up to max(1, K_round, sum of local candidate counts) rounds; stop early on an idle round under reliable delivery). Each recharger publishes a copied snapshot of its own members, candidate scores, estimated workloads and optional count limit to overlapping neighbors. It acts only after receiving all known neighbors' current-round snapshots. For each locally heard, unowned candidate it compares eligible (current group size, estimated workload after admission, S, ID) bids, and claims at most one worker per round. S = u1*wait + u2*travel + u3*earliness, computed locally from the worker broadcast and local primitive distances. Workers never bid or decide. Rechargers eligible for the same whole loop necessarily have overlapping regions, so contender comparisons need no global ownership table.
   *Unclaimed:* K_unclaimed local cycles each allow a bilateral offload followed by another auction round. Only feasible offload/exchange proposals enter a neighbor bid election. A claimant can give one member to a neighbor, or exchange members, and admit an unclaimed worker if both final groups respect any explicitly configured count limit. No utilization threshold is applied. The two rechargers select matching proposals and commit through acknowledged delivery. There is no global best-assignment search or global move budget. Bounded local negotiation may leave feasible assignments undiscovered.
4. **Overlap balancing** (disabled by K_swap=0; otherwise up to max(K_swap, N²) rounds, N = largest local candidate count; stop early if reliable delivery yields no improving pair): each recharger proposes its best improving transfer/swap using its own state and received neighbor snapshots. The lexicographic objective minimizes sum of squared group sizes, then squared estimated workloads, then total S. Thus travel improvements cannot undo count/workload balance; only mutually eligible workers move. Isolated rechargers can claim all eligible workers. This is local balancing, not a guarantee of a globally equal allocation or SMT feasibility. Each endpoint votes for at most one incident proposal; a pair proceeds only with matching votes. The proposer sends a commit, updates its own membership after acknowledged delivery, and the recipient updates its own membership from the received commit. Missing messages leave the transaction unapplied. These grouping rules use the synchronous simulator Bus delivery contract; an asynchronous ROS transport needs durable transaction IDs, locking and commit recovery. The simulator schedules actors and aggregates output; it does not choose owners or inspect other actors' state on behalf of a deciding actor.
5. **Plan per group (wavefront).** Priority = lower recharger ID; a group waits only for higher-priority **overlapping** neighbours (level = 1 + max level of higher neighbours); other groups run in parallel. Each group runs the two-shot SMT on its own workers with the region box and higher-priority neighbours' occupancy as **time-indexed** blocked cells (wrapped index 1..T'-1) for recharger sweeps and its own workers. It preserves its Phase 1 recharger start locations. T' must equal the neighbours' T': phase-1 T is tuned downward (<= K_T attempts) to hit it. If neighbour periods differ, the aligned solve is infeasible, or a neighbour plan is unavailable, the group plans unconstrained and is flagged **runtime fallback**. Plans or no-plan notices go to lower-priority neighbours (ACK/retry); a `ready` exchange acts as the start barrier. Phase 2 checks T' in ascending order; optional `phase2_optimize_cost` minimizes total primitive cost Y for the first feasible T'. Empty group: recharger parks at its anchor.
5b. **Group mode (testing):** `group_mode` = `two_shot` (default), `one_shot` (every group) or `auto` (groups of <= `one_shot_max_workers`). A one-shot group solves the repo's monolithic variant over a single hypercycle H (= neighbours' T' when aligned, else `one_shot_H`); everything else (region, neighbour constraints, alignment, fallback) is unchanged.
6. **Refinement** (K_refine > 0): each `Refiner` receives current-round neighbor state/plan snapshots and proposes a local transfer/swap that does not worsen the count/workload balance objective. The lower-ID proposer solves only its own trial group and sends the proposal to its peer. The peer independently solves its own trial with the received higher-priority plan, evaluates pair efficiency from received/local plans, and accepts only gains >= refine_min_gain. An acknowledged commit installs each endpoint's own plan. Missing messages, infeasibility and runtime-fallback trials leave the original plans in place. Each recharger has up to K_refine proposal rounds; there is no global attempt budget or winner selector. Pairs with other downstream plan dependents are excluded using local/received neighbor lists.
7. **Initial setup:** workers wait at their initial cells with full charge. Rechargers plan deployment in ID priority using local free cells and received neighbor setup paths, avoiding complete primitive sweeps, stationary workers, lower-neighbor anchors, and higher-neighbor final positions. Setup paths/readiness are periodically broadcast; temporary loss is retried on later periods. Neighbor AND/MAX exchanges establish planned readiness. A synchronized simulated controller advances each reserved movement only after current-position reports confirm the expected cells. No executable start ticks are issued until arrival is confirmed. `setup_timeout_s=2.0` limits communication/heartbeat silence only. Fresh stage/timestamp/position reports renew the watchdog even while motion is incomplete; movement may take longer than 2 seconds. A bounded poll call returns `WAITING` for ongoing healthy motion. Actual silence reports `TIMEOUT` and holds the barrier until explicit retry. Initial path/readiness requests also have a finite publication budget. Unreachable routes or unexpected off-route positions are `BLOCKED`. The controller interface is intended for a later ROS 2 adapter.
8. **Runtime:** the separate simulator uses 2-step reservations and ID priority. It counts delays but does not implement battery-aware repair of missed recharge appointments or full hypercycle resynchronization. The main pipeline returns the planned deployment and hypercycles; it does not execute them on robots.

## 4. Messages
Beacon, worker broadcast, candidate list, group_state, group_bid, group_offer, group_vote, group_commit, refine_offer, refine_accept, refine_commit, replan_notice, plan / no-plan, ready, setup_path, setup_ready, setup_position. Setup messages are periodic, unacknowledged publications with session/stage freshness checks for positions; a lost publication is not a failure declaration. Runtime delay updates remain a simulator extension rather than an implemented messaging protocol.

## 5. Failure handling (`failure.py`)
Heartbeat every hb_period steps; failed after k_missed misses: `declared_at = first missed slot + (k_missed-1)*hb_period`; ACK-retry exhaustion also marks a peer failed. A failed robot stops where it is and becomes an obstacle. **Worker:** owner drops it; owner and every lower-priority overlapping group (dependents) are re-solved in ID order. **Recharger:** survivors independently observe locally heard workers without a surviving owner in fresh neighbor snapshots. The same local auctions and overlap balancing protocol reassign them; no global orphan list is provided to a bidder. Workers with no eligible/capable survivor remain unserved. Each survivor requests its own replan after a local obstacle or membership change; replan_notice messages propagate along lower-priority neighbor links. The observer collects these requests and reports outcomes, without selecting owners or replan dependents. New plans start at the next hypercycle boundary; the model assumes a fresh start state then.

## 6. Outputs
Per recharger: group, start cell, recharger path, final charge-up schedule, T'. Lists: unclaimed/unserved workers with reasons, runtime-fallback groups, unreachable peers. `compare.py` prints the repo's hard/soft efficiency and explicit solver statuses. UNKNOWN is not UNSAT; a bounded phase-2 search with no plan reports SEARCH_EXHAUSTED. Unsuccessful centralized solves show n/a coverage and quality metrics. Table timing is measured pipeline wall time, including decentralized grouping/refinement/setup, not SMT-only time.

## 7. Known limitations
Per-group optimality only; workers outside every region are invisible; recovery assumes full-charge cycle boundaries; the utilisation estimate is a heuristic; runtime arbiter lacks hypercycle re-sync. Legacy worker files define abstract waypoint transitions. Optional explicit per-edge worker swaths are used by both SMT phases, neighbor reservations, verification, and runtime checks. Straight-line inference is a separate modeling variant and cannot recover unknown curved paths.

Grouping, refinement and recovery use per-recharger handlers with local state and received neighbor messages (`negotiation.py`, `refinement.py`, `RecoveryActor`). Shared dictionaries are simulation inputs/outputs and measurement state; they do not select assignment, refinement or recovery winners. The synchronous harness and acknowledged Bus remain simulation infrastructure, not a deployed ROS 2 transport or a proof of asynchronous fault tolerance. `outside_all_regions`, `loop_not_inside_any_region`, `unreachable_in_region`, `capacity` and `negotiation_incomplete` are observer diagnostics; the observer never feeds unseen workers into an agent decision. Automatic anchor placement is an optional experiment-setup aid; deployed controllers receive their physical anchors as inputs.
